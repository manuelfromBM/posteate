============================================================
1. POR QUE SE HIZO ESTO
============================================================

Se revisaron las pantallas del MVP (ver clasificados-platform/CLAUDE.md,
seccion 2) contra lo que ya existia en el frontend y faltaban:

- Crear publicacion
- Editar / eliminar publicacion propia
- Cambiar estado de una publicacion propia
- "Mis publicaciones" (panel del usuario)
- Reportar una publicacion

Problema encontrado antes de construir: el login NO es real todavia.
features/usuarios/hooks/useLogin.ts solo hacia un setTimeout falso, y
lib/api.ts no manda cookies ni token alguno. El backend SI exige usuario
autenticado para crear/editar/eliminar publicaciones (permission_classes
en publicaciones/views.py). Como pediste no tocar el backend, se te
pregunto como resolver esto y elegiste:

  "Auth simulada con localStorage" -> el login/registro guardan una sesion
  falsa en el navegador (no valida contra el servidor). Las pantallas de
  crear/editar/eliminar/cambiar estado quedan completas y conectadas a la
  API real, pero esas llamadas de ESCRITURA van a fallar con 401/403
  contra el backend real HASTA que exista un login real. Esto es
  esperado, no es un bug.

4. COMO REVISARLO VOS MISMO
============================================================

A) Revisar el codigo (sin correr nada)
---------------------------------------
  cd clasificados-platform
  git status                     -> confirma que backend/ no aparece
  git diff -- frontend           -> diff completo de lo modificado
  git status --porcelain frontend | grep '^??'   -> lista de archivos
                                                     nuevos

B) Probarlo corriendo el frontend
----------------------------------
  cd clasificados-platform/frontend
  npm run dev
  Abrir http://localhost:3000

  Flujos a probar:

  1. Registro real:
     /registro -> crea una cuenta. Esto SI pega al backend real
     (POST /usuarios/). Si el backend no esta corriendo, va a fallar
     ahi mismo (es esperado, es la unica parte que necesita backend
     levantado ademas de la lectura de publicaciones/categorias).

  2. Login simulado:
     /login -> pone cualquier usuario/contrasena (no se valida contra
     el servidor) y entra. El header debe cambiar a "Hola, <usuario>",
     "+ Publicar", "Mis publicaciones", "Salir".

  3. Crear publicacion:
     Click en "+ Publicar" (o ir a /publicaciones/nueva). Llenar el
     formulario y enviar.
     - Si el backend esta corriendo pero sin login real: vas a ver un
       mensaje de error explicando que la sesion es simulada y el
       backend rechazo la escritura (401/403). Esto es el
       comportamiento esperado, no un bug a arreglar.

  4. Mis publicaciones:
     /mis-publicaciones -> lista publicaciones cuyo "usuario_nombre"
     coincide con tu sesion simulada, con acciones de cambiar estado,
     editar y eliminar. Nota: solo mira la primera pagina de
     resultados porque el backend no tiene filtro por usuario todavia
     (ver limitacion en seccion 5).

  5. Detalle de publicacion + reportar:
     Entrar a cualquier publicacion (por ejemplo desde /buscar).
     - Si sos el dueno (usuario_nombre coincide con tu sesion): vas a
       ver Editar / selector de estado / Eliminar.
     - Si no sos el dueno: boton "Reportar publicacion" -> completa
       motivo y comentario -> enviar.

  6. Verificar que el reporte llego al admin:
     Ir a /admin -> el reporte que acabas de crear en el paso 5 deberia
     aparecer en la tabla (estado "Pendiente"). Si recargas la pagina
     completa del navegador, se pierde (vive solo en memoria de la
     sesion, no hay backend de reportes).

5. LIMITACIONES CONOCIDAS (a proposito, no son bugs)
============================================================

1. Crear/editar/eliminar/cambiar estado de publicaciones van a fallar
   contra el backend real (401/403) porque no hay login real todavia.
   El formulario ya detecta este caso y muestra un mensaje explicativo
   en vez de un error generico.

2. "Mis publicaciones" filtra en el cliente sobre la PRIMERA PAGINA de
   resultados de /publicaciones/ (20 items, paginacion default de DRF),
   porque el backend no expone un filtro ?usuario=. No es un listado
   completo ni paginado de verdad.

3. "Reportar publicacion" es 100% mock (vive en memoria del navegador,
   se pierde al recargar). El backend no tiene modelo Report todavia
   (dominio "Report" esta documentado en CLAUDE.md seccion 7 pero no
   implementado en clasificados-platform/backend).

4. Nada de esto toco el backend. Cuando decidan implementar login real,
   estas pantallas deberian empezar a funcionar de punta a punta sin
   cambios adicionales en el frontend (solo reemplazar
   features/usuarios/authStore.ts / useLogin.ts por llamadas reales).
